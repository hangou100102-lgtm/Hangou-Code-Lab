# 网页文字自适应（根字号随视口平滑缩放）

## Context

**需求**：给网页文字加自适应 —— 让字号随屏幕宽度自动缩放，而不是在断点处硬跳。

**为什么这么做**：站点目前全站字号挂在唯一一个开关 `html { font-size: 90% }`（[style.css L113-117](file:///e:/我的项目/Myblog/css/style.css#L113-L117)）下，72 处 `font-size` 全部是 `rem`，没有任何 `clamp()`，`vw/vh` 只用在布局上。也就是说「根字号」就是全站的等比缩放总闸 —— 项目此前那次「全站整体缩放 10%」也是调这个值。

**已与用户确认的取舍**：
- 范围：**整站等比缩放**（只改根字号一处，文字、间距、顶栏高度、避让距离全部随动，延续既有做法）
- 区间：**窄屏缩小、宽屏封顶** —— 窄屏约 13px，≥1024px 维持现在的 14.4px（桌面观感完全不变）

**预期结果**：320px 视口下根字号 ≈13px，≥1024px 恰为 14.4px，中间线性过渡，无台阶。

---

## 实现方案

### 唯一必改点：根字号（style.css L113-117）

把 `font-size: 90%;` 换成「回退 + 流体」两行：

```css
html {
  /* 整体缩放：根字号随视口宽度平滑缩放，全站 rem 尺寸（字体/顶栏/间距/避让）等比联动。
     - 320px 视口 → 13px（默认字号 16px 的 81.25%）
     - 1024px 及以上 → 14.4px（现有 90%，桌面观感不变）
     - 中间线性过渡：R = 77.2727% + 0.19886vw
     - 中间值必须含 vw；写成常量百分比（如 clamp(13px, 90%, 14.4px)）会恒等于 14.4px，等于没写
     - 用百分比而非 px 做锚点：保留「跟随浏览器默认字号」的可访问性，与原 90% 语义一致 */
  font-size: 90%;
  font-size: clamp(81.25%, calc(77.2727% + 0.19886vw), 90%);
  scroll-behavior: smooth;
}
```

**系数推导**（两个锚点：320px→13px，1024px→14.4px）：

```
斜率 k = (14.4 - 13) / (1024 - 320) = 1.4 / 704 = 0.00198864 px/px = 0.19886vw
截距     = 13 - 0.00198864 × 320 = 12.36364px = 77.2727%
```

**关键点验算**（浏览器默认字号 16px 时）：

| 视口 | 夹取后根字号 | 说明 |
|---|---|---|
| 320px | 13.000px | 触底 |
| 375px | 13.109px | |
| 768px | 13.891px | |
| 1024px | 14.400px | 触顶 |
| 1280px | 14.400px | 与 1024 完全相同，封顶生效 |
| <320px | 13.000px | 触底保护 |

首行 `font-size: 90%;` 是不支持 `clamp()` 时的回退（整条声明被丢弃），与现状一致。

### 配套不改的东西（均经过逐项评估，无一处需要联动修改）

- **10 处 px 字距**（-0.5 / -0.2 / +0.2px）：根字号最大只缩到 90.28%，px 字距不缩放，导致其相对 em 值放大约 10%，绝对偏差 <1px，肉眼不可辨 → 保持不动。
- **[.home-hero p 的 0.1775em 字距](file:///e:/我的项目/Myblog/css/style.css#L487)**（用于让中文副标题宽度对齐标题）：`em` 与标题的 `rem` 共享同一根字号，两者宽度比恒定 → 对齐关系自动保持。复核项见验证第 7 条。
- **所有 rem 依赖**（`4rem` 顶栏三件套、`6.5rem` 顶部避让、`calc(100vh - 4rem - 24px)` 首屏居中、`calc(100vh - 9rem)` 目录高度）：都是自洽的等比组合，一起缩不会失衡。
- `index.html` 的 viewport、所有 `.tsx`、`public/giscus/*.css`（giscus 在 iframe 内，不继承本站根字号）。
- **不删**死代码 `.hero` / `.hero h1` / `.hero p`（L1358-1380，无任何组件引用；640px 断点里的 `.hero h1 { 1.75rem }` 同样是死代码）—— 与本次任务无关，不顺手清理。

## 验证

### 一、静态与算术复核（零成本，先做）

1. `font-size:\s*[0-9.]+px` 全文件应零命中 → 无 px 字号漏网，全站字号都吃根字号联动。
2. 新 `clamp()` 内只出现 `%` 与 `vw`，不得出现 `rem`/`em`（避免根元素自引用）。
3. 手算上表五点，确认触底 13、触顶 14.4、1280 仍 14.4。

### 二、浏览器实测

本地起 `npm run dev`。因为浏览器子代理不便直接改视口宽度，**用 iframe 法测窄屏**：在页面里注入一个指定宽度的 iframe 指向 dev server，读其 `contentDocument` 的计算字号（iframe 内的 `vw` 即 iframe 自身宽度）。

```js
// 对 320 / 375 / 768 分别执行
const f = document.createElement('iframe');
f.style.cssText = 'width:320px;height:800px;border:0';
f.src = '/';
document.body.appendChild(f);
f.onload = () => {
  const d = f.contentDocument;
  console.log(getComputedStyle(d.documentElement).fontSize);          // 期望 13px
  console.log(d.querySelector('.nav').offsetHeight);                   // 期望 52
  console.log(getComputedStyle(d.querySelector('.home-hero h1')).fontSize); // 期望 29.44px
};
```

宽屏（1024 / 1280）直接在真实视口下量：

```js
getComputedStyle(document.documentElement).fontSize            // 两个宽度都必须等于 14.4px
document.querySelector('.nav').offsetHeight                   // 必须等于 57.6
getComputedStyle(document.documentElement, '::before').height  // 必须与 .nav 同高
getComputedStyle(document.querySelector('.article-body')).fontSize // 14.98px
```

**判定要点**：

1. **封顶生效**：1024 与 1280 的根字号、`.nav` 高度必须完全相同（14.4px / 57.6px），证明桌面观感零变化。
2. **平滑无台阶**：641、768、1024 这几个断点两侧的根字号应连续变化，不出现跳变。
3. **触底保护**：视口小于 320px 时根字号仍为 13px。
4. **顶栏三件套同高**：`.nav` 高度 = `html::before` 高度 = `.nav-drawer` 的 `top: 4rem`，三者始终一致（任一不同高就会露出模糊层错位/抽屉被顶栏压住）。
5. **首屏垂直居中未破坏**：320×640 下 `.home-hero` 实际高度应 = `640 - 52 - 24 = 564px`，内容中心与视口中心偏差 <5px。
6. **无横向溢出**：各宽度下 `documentElement.scrollWidth <= clientWidth`。
7. **字距对齐回归**：同一切 320 与 1280，比较 `.home-hero h1` 与 `.home-hero p` 的 `getBoundingClientRect().width` 比值，变化应 <1%，且副标题换行行数一致。
8. **窄屏抽屉**：打开导航抽屉与 TOC 抽屉，确认顶部留白仍刚好让出顶栏，不重叠不悬空。

## 风险

| 风险 | 评估 | 处理 |
|---|---|---|
| 顶栏三件套（`.nav` / `html::before` / `.nav-drawer top`）不同高 | 三者都用 `4rem` 表达，天然同步 | 上线后按验证第 4 条复核 |
| 窄屏「文字缩了但水平留白没缩」（`32px`/`14px` 固定 padding） | 这是「只改根字号」方案的预期内取舍，用户已选择该范围 | 接受；若将来要改，另起一次改动把结构性 padding 纳入 vw |
| 窄屏抽屉顶部留白偏紧（`5.5rem` 在 320px 下让出 19.5px，桌面 21.6px） | 按比例收缩，仍够用 | 若实测标题离顶栏 <12px 再单独微调 |
| `100vh` 在移动端含地址栏区域，首屏中心本就偏低 | 与本次改动无关 | 不混做；如需修另改 `100dvh` |
| 用户把浏览器默认字号改大（如 20px） | 百分比锚点会随之等比放大，属可访问性正确行为 | 保持 |
